# 结果证据检查器

`../scripts/check_evidence.py` 为原创、只读、Python 3.9+ 标准库工具。检查声明的文件快照与数值字段，不执行求解代码、不解析整篇论文、不自动核实单位、模型正确性或赛事规则。

```bash
python3 scripts/check_evidence.py assets/evidence-example/manifest.json
```

示例是确定性的**合成结果**，不代表真实赛题。脚本输出 JSON：`PASS` 只表示声明的文件哈希和数值一致，`FAIL` 表示缺失/空文件、哈希或数值冲突，`ERROR` 表示数据契约错误。退出码依次为 0、1、2。合成/未验证声明仍输出警示，不自动升级其可信状态。

## 台账格式 version 1

完整示例见 [manifest.json](../assets/evidence-example/manifest.json)。路径全部相对于台账所在目录，不能越出该目录（含符号链接）；将台账放在实际项目根目录即可覆盖子目录。脚本不会自动刷新哈希或改写数据，以免掩盖上游变更。

- `artifacts`：非空列表；每项具有唯一 `id`、相对 `path`、64 位小写 `sha256`。可登记输入、代码、配置、结果、图源、正文、编译日志等需要锁定的文件，供人检查依赖完整性。哈希只检测登记快照后的变化，不能证明产物确由这些输入生成。
- `claims`：非空列表；每项有唯一 `id`、来源 `artifact`、`pointer`、数值 `value`、`unit`、`status`、`location`。
- `pointer`：指定 JSON 文件的字段，空串表示根值；`/q1/rmse` 表示嵌套字段，`/values/0` 表示数组首项，键中 `/` 与 `~` 分别写为 `~1` 与 `~0`。不接受负索引或不存在的字段。
- `value`：台账中待用于文稿的显示数值，必须为有限 JSON 数，不接受布尔、数字字符串、NaN/Infinity。保留指标与题号，例如“Q1 验证集 RMSE”，不能只登记一个散落的数字。
- `scale`：可选、正数、默认 1；先将来源乘以它，例如比例转百分数用 100。`unit` 为转换后的单位，脚本不会自行推断它。
- `abs_tol`、`rel_tol`：可选、非负、默认 0；比较 `abs(value - source*scale) <= max(abs_tol, rel_tol*abs(source*scale))`。采用 Decimal 避免二进制浮点显示误差。显示两位小数可指定绝对容差 0.005；容差需有精度依据，不得为掩盖数值冲突任意放大。
- `status`：`measured`（观测）、`model_estimate`（模型预计）、`synthetic`（合成示例）、`unverified`（尚未核验）。这些是作者声明，不是检查器给出的科学验证结论。
- `location`：待核对的正文/图表位置描述，如“摘要及表 3 的 RMSE”；这是供审阅定位的元数据，脚本不自动验证该位置是否存在或已填入该数值。

只有约定的字段被接受；重复 JSON 键、重复 ID、未知来源、负容差、错误指针或非有限值均拒绝。新增需要的字段先修改契约，避免拼写错误被静默忽略。

## 使用顺序与局限

从真实运行生成结果文件；验证模型后登记快照和关键指标；用台账生成正文/表格或逐项核对；最后运行脚本并结合 [交付验收](delivery-review.md) 审阅语义、引用、编译与页面。

哈希失配时先确定输入/结果是否有意更新，再按依赖重算与更新台账，不能只换哈希保住通过状态。检查器不检测未登记文件、不读取 Excel/CSV 指标、不做公式符号推理，也不以声明 `location` 代替实际正文检查。其他数据格式可由已有求解程序导出关键指标 JSON，并保留原附件快照。
