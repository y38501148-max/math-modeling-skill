# 通用事件时间表检查器

运行 `python3 scripts/check_schedule.py path/to/schedule.json`。只有 Python 标准库依赖，不运行下载的第三方代码，也不访问网络。结果为 JSON；退出码 0 表示已声明检查全部通过，1 表示发现约束违反，2 表示输入结构无效。

## 输入契约

- `schema_version: 1`；`units` 指定共同时间单位，脚本不做单位换算。
- `horizon` 为正数，所有操作必须在 `[0,horizon]` 内结束。
- `resources` 是资源名到配置的映射。**每种资源都是容量为 1 的独占资源**；可选 `unavailable` 是停机区间列表。
- `operations` 为非空数组。每项必须有唯一 `id`、非空 `resources`、`start`、`end`，且 `0≤start<end`。多资源操作同时占有列出的全部资源。
- 可选 `min_duration` 是最低时长，省略时仅检查正时长；`release` 默认为 0，`deadline` 默认为 `horizon`。
- 可选 `predecessors` 为前置操作 ID，或 `{"id":"前置ID","lag":2}`；要求当前开始不早于前置结束加非负延迟。脚本检查缺失前置项和环。
- 区间采用 `[start,end)`，相邻操作可在同一时刻交接。`--tolerance` 是所声明时间单位中的绝对容差；过大的容差会掩盖小冲突，应按数据精度选。

可运行示例为 [schedule-example.json](../assets/schedule-example.json)。它描述两次搬运、中间加工与停机日历，仅用于演示，不是 2018 B 的答案。

## 检查内容

检查资源重叠（包含嵌套区间）、维修时段占用、最小时长、释放/截止时刻、班次上限、前后关系和循环依赖。输出包含具体资源、操作 ID 和违反的时间范围。

## 用于 RGV 时必须补的语义

先从题目独立生成全部操作和正确的资源占用，不要从优化器目标函数抄验证逻辑。运输时间、运动位置连续、刀具类型、工件携带容量、清洗规则、完成件计数、故障概率与报废语义均需另加专项校验。零时长里程碑、并行容量大于 1、可抢占任务不属于该脚本的数据模型；先转换为实际资源与正时长段，或修改检查器并测试。

**输入未声明的限制不会被自动检查。** 例如未给 `min_duration` 时，它不能发现加工时间被缩短；未把运输列成操作时，它不能发现车辆瞬间移动。因此输出 `valid:true` 只表示这个显式事件模型通过检查，不证明完整赛题方案可行，更不证明最优。
