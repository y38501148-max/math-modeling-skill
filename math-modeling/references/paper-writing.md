# 从计算结果写成本科建模论文

依据W01、R07、案例论文及用户提供的写作经验和成稿样例提炼；新两份PDF的页码、采用与修正见[写作资料评析](writing-source-review.md)。经验建议用于改善论证，不作为赛事规定。2026本科国赛先读[专用规则](cumcm-2026-format.md)：摘要含标题与关键词原则上1页，正文无目录且不超过30页，AI声明置于参考文献前；不擅加全国规范未要求的字体、行距或英文摘要。

## 先分清各部分的职责

| 部分 | 读者应获得什么 | 避免重复或遗漏 |
|---|---|---|
| 标题 | 研究对象/任务，必要时点出真正主导的方法 | 不堆算法名，不强制套“基于XX的XX研究” |
| 背景与重述 | 为什么研究，以及题目具体要求交什么 | 压缩背景；重组题意但保留原题编号、子任务、硬约束与附件格式 |
| 问题分析 | 每问的难点、抽象理由、方法选择及前后依赖 | 比摘要更具体；通常不重复最终数值，也不写成算法宣传或完整推导 |
| 建模前准备 | 本问输入、筛选依据、预处理、固定参数和前问输出 | 放在相关模型前；明确实际做过什么，不与问题分析重复 |
| 建立与求解 | 数学对象、实现和结果如何得到 | 核心原理留正文，通用算法介绍只保留理解本题所需内容 |
| 结果与检验 | 本问答案、证据、误差和可用范围 | 图表后明确写出结论，不让读者自行从图中猜答案 |

默认按题目组织正文，使摘要、问题分析、模型与结果能按同一问对上；多问共享模型时统一定义，后续只写新增目标、约束和参数变化。也可按模型组织，但须明确每节回答哪些问题。章节编号按实际结构连续生成，不照抄经验文档中的跳号或固定章节数。

每问形成`题目要求 → 模型定义 → 参数来源 → 求解方法 → 数值/方案 → 检验 → 适用范围`。全文按论证组织，不把尝试过程、失败日志和分工叙事写成主线；不为凑章节拆散紧密相关的模型与检验。

## 标题、摘要与关键词

标题保持简短、具体，与实际完成的工作一致。方法主导全文时可以入题；仅局部使用的算法不应抢占标题，也不靠“高精度”“最优”等词预先承诺结论。

结果稳定后写摘要。先简短说明研究对象和总任务，再逐问交代问题、核心模型/方法与主要结果；只有求解手段影响可信度或具有实质特色时才展开。每问可用一段，但不强制段数或每段复用同一句式。给出少量有区分度的关键数值、单位和条件；判断类问题也要明确最后得到什么结论。

结尾可用一两句写检验效果或适用条件；前面已经完整时不为凑“总结段”重复。用题号和真实依赖自然衔接，不机械堆“首先、其次、然后、最后”。排版允许时可克制加粗核心方法和结果，不能整段加粗或用强调代替证据。

关键词覆盖研究对象、主要模型与求解方法。经验文档建议3～5个，可作无另行要求时的参考，不是全国强制数量；不要为凑数加入未采用方法或空泛的“数学建模”。

摘要应可独立阅读，不依赖“见表X”、正文才定义的符号或冗长公式。结果来自仿真时保留条件，例如“在所设到达/故障机制下，模拟结果为……”。缺少数据时给出方案摘要并明确尚无实证结果，不补造精度或改善幅度。定稿时从摘要逐问反查正文和结果台账，核对任务、方法、变量含义、数值与证据状态。

## 假设、符号与完整模型

假设在分析和建模中产生，说明简化了什么、为何合理以及失效时影响哪些结论。不把题面给定条件伪装成创新假设，不用“数据真实可靠”“忽略其他因素”掩盖未检查问题，也不把题目硬约束移到局限中事后豁免。固定参数、初值及数据筛选交代来源和用途。

符号表优先收录跨章节或反复使用的量，列含义、单位与必要下标集合；局部辅助变量在首次出现处定义即可，列入符号表的量也应在正文首次使用时解释。区分标量、向量、角度、概率、数量与流率，避免一符多义。解释软件参数与数学符号的对应，例如旧文ARIMA参数顺序可能不同。

优化写变量域、目标和约束；PDE写初边值及交界面；仿真写实体、状态、更新顺序、随机机制和终止规则。公式前交代为何引入，公式后解释关键量及与下一步的关系。算法写本题的输入、参数、停止条件和输出，不用“由MATLAB得出”代替方法。

## 结果段与图表

每问结果段至少明确答案、条件和单位；数值精度遵循题面及实际计算可信度，评价/预测结果结合表图，开放问题给出有依据的判断及适用边界。不能仅贴一张图、软件截图或结果附件就结束该问。

每幅结果图在正文有可定位的解释：指明观察的系列或子图、主要趋势/差异及必要数值，再说明它如何支持本问结论。多子图用“图X(a)/(b)”分别对应，少用容易随分页失效的“上图”。解释实际现象，不把所有曲线都描述为“明显提升、稳定可靠”。

| 论证目的 | 合适图表 | 一起说明 |
|---|---|---|
| 数据条件 | 分布、缺失统计、指标表 | 样本范围、单位、筛选与来源 |
| 标定和预测 | 观测/拟合、残差、回测和区间 | 拟合与留出区间，误差尺度 |
| 调度可行性 | 甘特图或事件表 | 资源、移动/加工、故障和班次 |
| 多目标选择 | Pareto图、方案指标表 | 硬约束、偏好及推荐理由 |
| 仿真比较 | 配对差异、分位数/分布图 | 重复次数、随机条件与截尾处理 |
| 稳健性 | 参数扰动与决策变化图 | 固定方案还是每次重优化 |

结果图与表格从同一版本数据生成。组合图保留子图标识、尺度/色标含义和可读字号；长表区分真零、缺失和不适用，用表注明确空白含义。技术路线图只在帮助理解时绘制，呈现各问输入、方法、输出和真实依赖，不复制别人的箭头关系。具体制作及版面检查见[图表指南](visualization.md)。

## 检验、评价与改进

检验可紧随每问结果，也可集中成章；章节位置可选，支撑核心结论的必要验证不能省略。按风险选择可行性、基线、误差或敏感性等检查，见[验证方法](validation.md)，不为凑章节把所有检验都做一遍。

优点连接证据，例如“事件推进减少空迭代，相同参数下与逐秒基线的完工数一致”；局限交代来自哪些假设/数据缺口，会影响什么，如何改进。不要求缺点条数少于优点，不为显得完整而凑条目，也不把足以推翻答案的问题轻描淡写为普通不足。

区分尚未实施的改进建议和已经完成的模型改进；后者要给改动、同口径比较及验证。成熟方法不直接称原创；创新定位于具体结构、约束、估计或算法改动。不把当前最好可行解叫全局最优，不把百分点当百分比，不从收敛图好看推出模型正确。正文与摘要中“精确、显著、最优”等措辞均须有相应证据。

将技术结果转成执行建议：谁执行、何时执行、采用哪些参数、何时切换策略。MCM/ICM要求memo/letter时写给指定读者，不自动给每篇添加同一封信。区分观测、模型推断、仿真估计和建议；远期预测不冒充已发生事实，参考答案不作为修改计算结果的目标。

## 引用、附录与最后核对

参考文献覆盖实际用到的背景、模型、算法和数据来源，在使用处标注；条数取决于引用需求，不沿用样例“只列三条”。核实条目信息，不能复制示例中的工具版本和日期；AI披露按该届规则，不能仅把AI名称列进参考文献就视为完成。

附录保存复算所需代码、参数、数据说明和题目要求的完整结果。2026国赛附录须收录全部完整可运行源代码（含Excel/SPSS交互命令）及支撑材料文件列表，不能只留核心片段或外部链接；可运行源文件同时放入支撑包。长代码附录不等于代码已齐全或能运行，需要对照实际文件和运行结果核验。

写作前接收实际模型、运行记录及图表清单，确认各问采用的版本；定稿时核对摘要、正文、图表、引用、附录和提交附件的数字、单位、文件名/后缀、版本。文件清单指向本次实际产物；只有参考PDF时不能声称已有其可编辑模板或附件。构建、渲染和最终状态见[交付验收](delivery-review.md)。

仅润色时保留数学语义与数值。发现公式、数据或假设有误，指出受影响章节，修正后同步关联结果；尚未复算的原文数字保持归因，不替作者背书。章节样例中的预填指标、参数、结论均须由本题证据替换，复盘时连接原始数据、公式、实现与结果，参见[案例补充](casebook-expanded.md)。
