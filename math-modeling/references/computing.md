# 把模型落实为可复算程序

## 只检查本任务需要的环境

先复用项目环境和用户指定工具。数值计算检查对应解释器、求解库及版本；Excel 附件检查读取能力；交付 PDF 再检查所选排版引擎、字体和页面渲染工具。缺少 DrawIO 不应阻断无需流程图的求解，缺少 LaTeX 不应阻断已有 Word 项目。不为默认流程安装整套软件。

记录实际解释器/依赖版本、运行目录、命令、配置和随机种子。代码、结果、图表使用显式路径；避免依赖 notebook 隐藏变量或前一次运行留下的缓存。若 notebook 是交付物，重启内核按顺序执行；脚本则在新进程运行入口。

## 从接口开始逐问实现

每问定义输入字段、变量维度、输出结构和验证函数。先用可手算小例检验方向、边界与索引，再运行真实附件。代码更换了算法或简化了假设，需同步数学描述和相关验证；不能报告计划中的模型却交付另一实现。

- 数据读取后核查形状和记录数；join 后检查重复增殖，数组运算检查广播维度和轴，不能依赖“没有抛异常”。
- 最大化问题用最小化接口时，明确符号转换并恢复原目标。按所用 API 核对约束语义：SciPy `minimize` 旧式字典 `ineq` 表示非负；`LinearConstraint` 使用上下界 `lb <= A @ x <= ub`。不要推广成“所有 scipy 约束都是同一方向”。见 [minimize 官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.minimize.html) 与 [LinearConstraint](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.LinearConstraint.html)。
- 精确整数模型记录整数可行性；连续松弛取整后重算硬约束，违反时修复或求整数模型，不能沿用松弛目标值。
- 保留原始优化结果的终止原因、时间、可行性、有效界和差距。异常/超时后不得把旧结果当作新结果覆盖发布。
- 验证器从导出方案独立计算限制与目标，不与求解器共用唯一评分实现。

## 实验预算与数值稳定

依据用户时限和问题规模安排基线、试跑和改进预算，先测小规模耗时。需要降维时保留物理含义，不设置“超过某维必须换算法”的万能阈值。

对异常结果先检查数据/单位、目标符号、约束方向、边界和求解状态，再调超参数。保留失败日志和最近有效结果，不无上限重试。随机实验的重复次数由区间宽度、稀有事件概率和比较目的决定；步长/网格容差由关键输出与决策阈值决定，不固定为五次、一万次或百分之一。

非有限结果（NaN/Infinity）不作为有效输出。原始数据保留足够精度，统一在展示层舍入；接近硬阈值时用未舍入值判断可行性。单位换算、相对提升和百分点在计算层产生，并保存参与计算的分子分母。

## 保存什么

保存原始输入标识与哈希、数据划分、拟合预处理、完整配置、模型与代码版本、命令、运行状态、结果/检查日志及图表数据。缓存应关联输入和配置版本；不能靠相同文件名判断有效。

可将每轮结果放入独立 run 目录，完成验证后在任务单标注当前采用轮次。只有用户需要的结果进入最终附件；用于复算的内部路径可以留在复现说明或附录，正文用业务含义解释算法与结论。
